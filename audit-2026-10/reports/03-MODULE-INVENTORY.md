# 03 — Module Inventory & Functional Coverage Matrix

*Source: two independent read-only code inventories (ticket-flow modules; admin/reporting modules) cross-checked against the freshly-migrated audit DB. Paths relative to repo root. Items marked **[UNVERIFIED]** could not be confirmed from code/audit DB. Oddities that are defects are carried into `13-MASTER-DEFECT-REGISTER.md` (ID in brackets).*

## Cross-cutting facts
* Roles (`user_role`): `user` (Requester) · `agent` (Technician) · `manager` · `admin` · `platform_owner`. "Agent-tier" = agent and above; manager+ is treated as on every team of the org.
* `proxy.ts` = exact allow-list of 11 public API routes (+ `/csat/*`, `/approve/*` token pages); everything else needs a session (`getClaims`). `getCurrentProfile()` trusts the proxy-set `x-verified-user-id` header.
* Enforcement = app code + RLS. **The status machine exists only in app code** (`lib/constants/request-transitions.ts`, `lib/requests/status-change.ts`); no DB trigger, no CHECK. Only 3 triggers on `requests` (org id, request no, updated_at). Activity/notification rows are written app-side with the service-role client.
* Cron = Windows scheduled tasks calling the app with `CRON_SECRET`: alerts (30 min), business-rules (15), email-reply-sync (1), csat (30). **No job reads `scheduled_reports`.**
* `next.config.ts`: `typescript.ignoreBuildErrors: true`; no CSP / nosniff headers anywhere. Rate limiter is in-process memory, keyed on first `X-Forwarded-For`.
* Separate `api/` Express worker (IMAP/Gmail/Graph sync, rule + LLM classification): no tests, no deploy evidence **[UNVERIFIED in prod]**.
