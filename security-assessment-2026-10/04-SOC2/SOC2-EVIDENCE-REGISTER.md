## How to read this

This register lists every piece of evidence that an independent auditor would be likely to ask for in a future SOC 2 Type II examination, one row per item. A Type II examination looks at whether controls **worked over a period of time**, so most items are records that are made again and again (monthly exports, sign-offs, restore tests). The column **Current status** says honestly where each item stands today (2026-10-15):

| Current status | Meaning |
|---|---|
| **Exists in repo** | A written procedure or tool exists in the repository. This only shows the control is *designed*. It is **not** proof that anyone operates it. |
| **Partly exists** | Something relevant exists (a log the application writes, a one-off result, a list) but it is incomplete, was not collected for a period, or its production state could not be verified from the repository. |
| **Not collected** | The record could be produced today, but nobody has produced or kept it. |
| **Cannot exist yet** | The record cannot be produced even if someone tried, because the process, approval, tool or named owner it depends on does not exist yet (for example, there is no approval step for creating accounts, so no approval records exist; there is no off-server backup, so no copy log exists). |

**Evidence class** (from the assessment brief) shows the kind of evidence the item will be once it is collected: A = our own technical test results, B = repository evidence, C = authorised organisational evidence (approved policies, signed reviews, real operating records), D = documentation only. **No class C evidence has been supplied to the assessment so far.** Nothing in this register is marked as evidence of operation. No record may be created later and dated earlier than the day it was really made.

**Retention codes** (all PROVISIONAL; management and the auditor decide):

| Code | Retention |
|---|---|
| RET-A | The whole examination period plus 3 years |
| RET-B | Until the document is replaced, plus 3 years after it is replaced |
| RET-C | System Log audit and security rows are kept 7 years by the application configuration (class B fact, `SYSTEM_LOG_AUDIT_YEARS`); exported copies kept as RET-A |

**Owner roles** are placeholders. Names: to be assigned by management (see SOC2-CONTROL-OWNER-MATRIX.md). Control IDs C01 to C16 are explained in SOC2-TYPE-II-CONTROL-OPERATION-PLAN.md.
