## Your eight questions
1. **What security issues did you find?** 70 distinct weaknesses (1 Critical, 3 High, 34 Medium, 32 Low). The five that matter most: (a) the live framework version has critical published flaws incl. Windows remote-code-execution; (b) the "nobody changes priority/SLA" rule existed only on screens — a technician/manager could still do it directly, and anyone could create a forged ticket directly; (c) private internal notes leaked: their start went by alert/e-mail to people who must not read them, and files attached to them were downloadable by the requester; (d) employees could read all colleagues' mobile numbers and could write on any ticket by e-mail with a guessed number; (e) HTTP only + shared default import password.
2. **What did you fix locally?** 29 findings: the framework upgrade; database migration 164 (priority/SLA, forged tickets, config tables, mobile numbers, internal-note files, reset flag); internal-note alerts and files; e-mail reply participant check and auto-reply loops; log-flood and login-CSRF; manager guards on user edits; zip-bomb preview; OEM preview injection; approval-code guessing and subject leak; and more. Each is in `05-REMEDIATION/01-CHANGE-LOG.md` and `02-VAPT/VAPT-MASTER-REGISTER.md`.
3. **What is still vulnerable?** 41 not fully closed: HTTP (decision), default password (decision), the rest of the technician/manager ticket-edit rights (design), manager powers over rules/workflows/settings (decision), about 20 config tables, approval side doors, project/task policies, several Low items; and two unverified (live sign-up setting; large uploads). `05-REMEDIATION/04-REMAINING-TECHNICAL-RISKS.md`.
4. **Which ISO 27001 controls are missing?** 10 not implemented, 46 not verifiable (all people and physical controls), 14 only designed; clause-level: no approved scope, policy, risk method, roles, internal audit or management review. `03-ISO27001/ISO27001-ANNEX-A-CONTROL-MATRIX.md`, `ISO27001-CLAUSE-GAP-ASSESSMENT.md`, draft SoA.
5. **Which SOC 2 controls or evidence are missing?** Design gaps in 33 of 38 criteria; evidence: no access reviews, restore tests, change approvals, incident records, vendor reviews, training records; 26 of 33 control areas have no owner. `04-SOC2/`.
6. **Did any existing functionality break?** No. Default suite 1,760 passed / 0 failed (18 skipped by design), remediation 182 passed, VAPT suite 16 passed; type check clean; lint 0 errors; latency unchanged. Old tests that encoded the old rules were updated to the new rules (listed in the change log), not weakened. Behaviour changes users may notice: managers can no longer edit administrators, attach phone numbers or set reporting lines (administrators still can); the approval code is in the e-mail body, not the subject; a technician-only form field is not shown in reports to requesters.
7. **Is the local build ready for your review?** Yes for security review (build, type check, lint, all suites pass; app runs on the isolated copy). It is not a release candidate until the prerequisites are done.
8. **What must happen before production?** `05-RELEASE-PREREQUISITES.md`: release the framework upgrade first; confirm live settings (sign-up disabled, password length, migration history); backup + restore test; apply migration 164 with the app, restart PostgREST, keep the rollback; set secrets and `TRUSTED_PROXY_HOPS`; decide HTTPS and the default-password policy.
